# Design decisions

Agreements from the design session (grilling) of 26.10.2026. Every decision comes with a short rationale, so that half a year from now it is clear why things are the way they are.

## Project and repositories

1. **Repository split.** `plasma-tide` contains the theme and all of our own widgets. [QuotaApp](https://github.com/julia-lakomy/QuotaApp) stays a separate fork and serves only as the data service for AI Limits. Our changes in it (the Firefox session) live on a separate branch. The look of the AI Limits widget belongs to Tide. This way the author's parser fixes can be pulled with a plain `git pull`.
2. **Name and hosting.** The project is "Tide", the first variant is "Mist". A private repository on GitHub (account lakomytomaszdev). Commits in English, push only on explicit request.
3. **Installation by copy, not by symlinks.** `make install` copies to `~/.local/share` and makes a backup before every installation. The desktop does not depend on which branch happens to be checked out.

## Look

4. **Plasma style.** Our own "Tide" style derived from Breeze, with our own shapes (radii, borders, transparency). Colors still come from the color scheme. At the start (stage 1) it is Breeze with our colors, and the custom shapes arrive with the top bar and the dock.
5. **Window decoration.** Our own Aurorae theme generated from the palette, no compilation. Buttons on the right in the order minimize, maximize, close (butter, mint, pink). Klassy rejected, because there is no package in KDE neon and it needs a rebuild after every KWin update.
6. **Fonts.** Geist in the interface, Geist Mono for the widget numbers. Rider keeps its own fonts. SF Pro is out because of its license.
7. **Wallpaper.** Generated from the palette, flowing smoothly across the monitors. Easy to replace with your own.
8. **The Tide global theme** ties everything together and includes our own lock screen and loading screen. The login screen (SDDM) is a separate, custom theme installed system-wide. All three first as mockups and tested in test modes (`kscreenlocker_greet --testing`, `sddm-greeter-qt6 --test-mode`) before they reach the system.
9. **Logo.** To be chosen from the proposals on the canvas.
10. **Applications.** Konsole, Firefox (the lakomytomaszdev profile, through the system theme) and GTK applications in the Mist palette. Rider unchanged. The other Firefox profiles unchanged.

## Layout

11. **Main monitor (DP-2, 2560×1440):** a top bar with the global menu and a clock with the date, and a floating dock with widget tiles.
12. **Left monitor (HDMI-A-1, 1920×1080):** a slim top bar with the global menu and a clock, so that the application menu is on the same screen as the window. Plus a hideable sidebar on the left, outer edge with expanded versions of the widgets, slid out with the mouse or with the Meta+S shortcut. Not on the edge between the monitors, because that is where the mouse crosses to the other screen.

## Icons

13. **Three layers:** the base theme, the Tide overlay (aliases, folders, missing icons) and tiles generated from the originals for applications outside the theme.
14. **Muted glyphs in the dock: a decision after a trial.** The dock and the menu take their icon from the same source, so a muted application icon from the dock will also appear in the menu. We decide on real icons in three versions: everything colored, a direct mix, a mix on a shared tile. The fallback is our own "Tide Dock" widget.

## Working with AI

15. **Architecture.** A single user service `tide-daemon` (Python, PyQt6, D-Bus) as the only source of data. Widgets in pure QML read it through `org.kde.plasma.workspace.dbus`. KRunner, the shortcut and the notifications use the same service.
16. **Agents widget:** Claude Code and Codex (T3 Code drops out along the way). First reading the session logs (`~/.claude/projects`, `~/.codex/sessions`), hooks only when the latency starts to get in the way.
17. **Improvements:** a shortcut and a notification "go to the waiting agent", window color according to the agent state (a prototype first, because it is not known whether KWin rules can be switched on the fly), KRunner with sessions and projects. Focus mode goes onto the "later" list.
18. **Worktrees:** local data only, no `git fetch` and no VPN. Cleanup always with confirmation, without `--force`, and a branch is deleted only after merge. (Since decision 41, non-suggested worktrees can be removed with `--force` after a stronger confirmation — the `Remove` cleanup stays unchanged.)

19. **Agent session state (26.10.2026, #9).** Claude Code itself writes the state of a running process to `~/.claude/sessions/<pid>.json` (`busy`, `waiting`, `idle`), including waiting for approval — this is the main source, and the log is the fallback. Codex does not record approval requests, so we infer them from a tool call without a result after 10 s, with no new child process and with `approval_policy` other than `never`. A session waiting for more than 30 min is idle, sessions with no entry for a day are skipped. Both formats are undocumented, so the parsers ignore unknown entries and the tests rely on synthetic logs.
20. **QML library in every package.** Plasma installs widgets as separate packages, so `widgets/lib` is attached to each of them at assembly time (`widgets/stage.py`), together with `Tokens.qml` generated from the palette. The singleton is named `Tokens`, because `Palette` collides with a type built into QtQuick.
21. **AI Limits without tide-daemon (26.10.2026, #15).** The `org.tide.limits` widget reads the QuotaApp local API directly (`GET /status` every 10 s and when the popup opens, `POST /refresh`, `POST /open`), because the service already exists, has its own read cycle and we do not change its API. The token is not in the repository: `widgets/stage.py` copies it from the service's `config.json` into `Config.js` in the package (mode 0600), just as the QuotaApp installer does. Without configuration the package is built with an empty token, and the widget says what to install — a missing QuotaApp does not block `make install`. Replacing the old widget in the panel is a separate target, `make swap-limits-widget`, not part of the installation.
22. **Worktrees (26.10.2026, #12).** The list comes from `git worktree list` of the repositories found in `~/DevWorkspace` (up to 3 levels, without hidden and dependency directories). "Merged" is a branch tip that is an ancestor of the local `master`/`main`/`develop` — computed with a single `git rev-list --count`, which also gives the number of unmerged commits. The last-change date is the latest of the HEAD commit time and the mtime of the files from `git status` — cheap, because we read the status anyway; walking all the files every minute would be too expensive. Size like `du -s`, cached for 30 min. All the git work runs in a single worker thread, and `Remove` replies with a delay (delayed reply), so D-Bus does not stall. Before removal the repository state is read again. Opening in the terminal and in Rider is done by the service (`Open`), because QML cannot launch a program with a working directory, and the Rider script from Toolbox has to be found outside `PATH`.
23. **Jump to the waiting agent (26.10.2026, #10).** The Meta+A shortcut registers a small KWin script (`registerShortcut`), which calls `ActivateLongestWaiting` in tide-daemon. Rejected: registering in KGlobalAccel straight from the service: on Wayland in Plasma 6 shortcuts are handled by KWin, and the kglobalaccel D-Bus protocol is internal (key structures changed between KF5 and KF6, component activity depends on the client's lifetime) — a KWin script is a stable API, the shortcut survives a service restart and can be changed in Settings. Notifications go through `org.freedesktop.Notifications` with a "Przejdź" (Go) action; the same session gets one again only after it leaves the "waiting" state and re-enters it, and sessions waiting at service start are skipped. When a session stops waiting, the notification is closed. The longest-waiting one is the one with the earliest `sinceTs` among sessions with a resolved window.
24. **System widget on ksystemstats sensors (26.10.2026, #14).** CPU, memory, graphics card and disks from `org.kde.ksysguard.sensors`, because these are the same numbers as in System Monitor. Memory and disk percentage is computed from `used/total`, not from the `usedPercent` sensors: for `/` that sensor showed 88% (from the partition size from Solid) instead of the 90% from df. The graphics card sensors (ksystemstats then queries nvidia-smi) and the process list work only while the detail view is open. The chart and rings use the library (`BarChart`, `History`, `Ring`, `MeterBar`).
25. **A helper instead of mapping at assembly time (#14).** The disk sensor is named `disk/<UUID>/…`, so the mount point has to be converted to a UUID. This is done at run time by `widgets/system/contents/code/sysinfo.py` (mountinfo + `/dev/disk/by-uuid`, the same order as `idHelper` in ksystemstats), called through the Plasma5Support `executable` engine — if done at package assembly time, the mapping would go stale after a partition change. The same helper reads the largest processes from `/proc`: private memory from `statm`, grouping by program from `argv[0]`. Rejected: `ApplicationDataModel` from `org.kde.ksysguard.process` (it groups by cgroup, so agents started in a terminal would count as Konsole, and sorting the table in QML requires a proxy) and PSS from `smaps_rollup` (about 350 ms per read).
26. **The worktrees hint only from tide-daemon (#14).** For a partition above 85% the widget calls `org.tide.Daemon /Worktrees List()`; a missing area or service means just "Dysk prawie pełny" (Disk almost full). A worktree is assigned to a partition by the longest prefix among all mount points, so a worktree in `/tmp` (tmpfs) does not count toward `/`.
27. **Global theme and lock screen (26.10.2026, #19).** The `org.tide.desktop` theme only points to the Tide components; the installation writes `LookAndFeelPackage` and the lock wallpaper, but does not call `plasma-apply-lookandfeel`. That tool (`KLookAndFeelManager::save`) rewrites values into `~/.config/kdedefaults` and deletes keys from user files, so after uninstalling the components the default pointers to removed Tide themes would be left; setting colors, cursor and style again would add nothing, because the component installers do that. Without `--resetLayout` the tool does not touch panels (the layout is applied only with the `LayoutSettings` flag), but we do not even need that. The theme has no layout scripts or `[Wallpaper]` (the Tide wallpaper is per-monitor images, not a wallpaper package). Splash screen: `ksplashrc Theme=org.tide.desktop` in the theme (our own screen since #20, point 32).
    The lock screen in Plasma 6.8 comes exclusively from the shell package indicated by `plasmashellrc [Shell] ShellPackage` — the same value plasmashell uses, and the name of the panels file depends on it (`plasma-<shell>-appletsrc`). So the Tide screen is a shell package `org.tide.desktop` containing only `lockscreen/` and `X-Plasma-FallbackPackage=org.kde.plasma.desktop`; it works in `kscreenlocker_greet --testing --shell`. **To be decided: how to enable it in the real lock screen.** Every route changes where plasmashell gets its files from:
    a) a full copy of `org.kde.plasma.desktop` in `~/.local/share/plasma/shells/` with our `lockscreen/` — panels unchanged, but after a Plasma update plasmashell would read the old copy, so automatic resynchronization is needed (e.g. a user systemd unit run before plasmashell, comparing a checksum of the system files); recommended if the Tide screen is to work day to day,
    b) `ShellPackage=org.tide.desktop` — plasmashell would switch to a new panels file (`plasma-org.tide.desktop-appletsrc`), i.e. an empty desktop; rejected,
    c) stay with the Plasma screen with Tide's wallpaper, colors and fonts, until KDE brings back lock screens in global themes.
    **Variant a) chosen** (26.10.2026) — see point 31.
28. **KRunner (26.10.2026, #13).** A KRunner D-Bus plugin (`org.kde.krunner1`) in tide-daemon: Claude Code and Codex sessions from 30 days, projects and worktrees. The object is served by dbus-python on a separate connection named `org.tide.Daemon.KRunner`, because PyQt6 cannot build an `a(sssida{sv})` reply (an array of structs requires a type registered in C++); dbus-python and Qt share the default GLib loop, so everything happens in a single main thread. The history index holds only small metadata (title truncated to 100 characters) and only in memory — no cache file, at the cost of about 2 s on the first query after the service starts. It is built lazily on the first query and refreshed incrementally, with the same readers as the Agents area. The Codex thread title is also taken from the application database (`state_<n>.sqlite`, read-only), because Codex Desktop threads have no title either in the log or in `session_index.jsonl`. Resuming opens a new Konsole window (like "Otwórz" (Open) in the worktrees widget), and a session that is still running is brought to its own window instead of launching a second copy.
29. **Worktrees window instead of a popup (26.10.2026, #12).** The popup with 48 worktrees was too long, cleanup was all-or-nothing, and from the directory name it was not clear what the work was. The list moved to a separate "Tide Worktrees" window (QML launched by a small PyQt6 launcher with `QQmlApplicationEngine`, a `.desktop` file with `StartupWMClass` and `setDesktopFileName`, so that the dock shows the icon and name). Rejected: `qml6` as the launcher: the window would have the identifier `qml6`, and QML needs someone to talk to the service anyway (the Plasma D-Bus module outside plasmashell is an unnecessary dependency). The tile only summarizes and opens the window through `ShowWindow()` in tide-daemon (QML in Plasma cannot launch a program). Groups are computed by the service (`group`), not by QML, so that the tile and the window say the same thing and can be tested: first missing directories and main branches, then "W pracy" (In progress) (an agent or activity < 24 h — also a merged worktree that someone just left), then "Do sprzątnięcia" (To clean up) (`removable`), the rest "Do decyzji" (To decide). Removal only of the selected ones and with a confirmation listing directories and branches. The link to agent sessions (title, tool, last activity) reads only the beginning and end of the logs from 30 days by the `cwd` field, in a separate module (`worktrees/sessions.py`), so that it can later be replaced by a shared session index (KRunner).
30. **Agent state on the Konsole tab instead of the title bar color (26.10.2026, #11).** A prototype in a nested `kwin_wayland --virtual` (KWin 6.8.1): the KWin `decocolor` rule by window title switches on the fly without `reconfigure` (KWin recalculates rules with title matching on every title change), and a scheme with a tinted `[Colors:Header]` (the title bar color is taken from it, not from `[WM]`, when the scheme has a Header group) colors the bar in Breeze. In the Tide decoration nothing changes: Aurorae v2 (C++) draws colors solely from the SVG and `ActiveTextColor` from `Tiderc`, it does not read the window palette, and `ColorScheme-*` classes in the SVG would take global colors, not the window's. A KWin script will not get around it either — `Window.colorScheme` is read-only, `setColorScheme` is not a slot. On top of that, the rule distinguishes Konsole windows only by title (a shared class and process for all windows). The bar color would require our own decoration that reads the window palette (a QML theme for Aurorae v1 or a C++ plugin), i.e. a departure from decision 5 — postponed.
    So the marker from the fallback plan works, only better anchored: tide-daemon marks the **Konsole tab** in which the agent runs (`KONSOLE_DBUS_SERVICE`/`SESSION` from the process environment), through its D-Bus API — a title prefix "◐ " (working) or "◆ " (waiting) and a teal/peach tab color from the palette. The tab title goes to the window title, so the marker is also visible in the Tide title bar, in the task bar and in the window switcher when it is the current tab. The prefix goes into the title format (local and remote), so that it survives Konsole refreshes, and the displayed title is set immediately, because Konsole recalculates it only after terminal activity. The originals are in `$XDG_STATE_HOME/tide/konsole-tabs.json`; the tab returns to them when the session stops working and waiting, when the service shuts down and after its restart, and a title or color changed in the meantime by the user stays. Rejected: `demandsAttention` for waiting ones (only one state, KWin clears it on activation and will not set it on an active window — the notification from #10 does this anyway), a KWin effect tinting the window (too heavy), escape sequences to the terminal (that is the agent's stream, not ours). Other terminals and applications (kitty, Codex Desktop) have no tab API and stay without a marker.
31. **Muted glyphs in the dock (26.10.2026, #8, resolves 14).** The user chose our own muted glyphs in the Mist style for dock applications and the most frequently used ones: a rounded square in a dark shade of pastel and a single-color application mark in pastel. The same glyph is visible in the menu and in KRunner — accepted. Rejected: recoloring full-color icons (`tools/make_tint.py`): multi-shade icons looked smudged after being reduced to a single pastel. The mark comes from the theme's symbolic icon (KDE), from Simple Icons (brands; CC0) or from a hand-made mark in the repository (T3 Code, VS Code — Simple Icons does not have their logos); we do not copy brand logos by hand. Simple Icons are downloaded at build time and not kept in the repository: the version is pinned and every logo has a SHA-256 sum in `glyphs.json`, so a replaced file will be rejected. The downloaded SVG is rendered only by rsvg-convert and we take only its transparency mask. When the source is unavailable (e.g. no network at the first sync), the application keeps its own icon with a warning, instead of aborting `tide-icons sync`. The glyph also overrides generic names used by KDE applications (`utilities-terminal` for Konsole, `preferences-system` for Settings), so it appears everywhere a program asks for that icon in color, e.g. in Dolphin's "Otwórz terminal" (Open terminal) action; the `-symbolic` versions stay from the theme. Our own "Tide Dock" is not needed.
32. **The shell copy with the Tide screen and its synchronization (26.10.2026, #19).** `make install` copies the whole `/usr/share/plasma/shells/org.kde.plasma.desktop` to `~/.local/share/plasma/shells/` and replaces only `contents/lockscreen` (from the `org.tide.desktop` package). Verified in a nested KWin with a temporary home directory: plasmashell reads all shell files from the copy (strace) and loads the existing panels, and `kscreenlocker_greet --testing` without `--shell` finds the copy by itself and shows the Tide screen. The freshness of the copy is guarded by the unit `tide-shell-sync.service` (oneshot, `WantedBy=plasma-workspace.target`, `Before=plasma-plasmashell.service`): `plasma-plasmashell.service` is pulled in by `plasma-core.target`, required by `plasma-workspace.target`, which starts startplasma, so everything is in one transaction and `Before=` works. `graphical-session-pre.target` rejected — it is also in this transaction, but it applies to every graphical session, and plasmashell is not ordered after it anyway. No `Requires=`: a synchronization failure does not stop plasmashell.
    The freshness criterion is a SHA-256 fingerprint of the content of the system package and the Tide screen, stored in the copy (`tide-shell-copy.json`), and not the package version (empty in the shell's `metadata.json`) or the modification time (dpkg preserves times from the package, and a restored backup would have its own). Computing takes a few dozen milliseconds, so logging in does not get longer. A new copy is created outside `plasma/shells/` and before the swap it is checked with a real greeter off-screen; when the Tide screen does not load, the copy is removed entirely (the system wins), and the "fallback" state suspends further attempts until the next fingerprint change. A manual removal of the copy (the rescue method) is remembered as "removed" and synchronization does not undo it — only `make install` restores it. Rejected: symlinks to system files instead of a copy: after a Plasma update the copy would lack new files, and links to removed ones would lead nowhere, so synchronization would be needed anyway.
33. **Loading screen (26.10.2026, #20).** `contents/splash/Splash.qml` in the global theme is a reworked Breeze screen (GPL-2.0-or-later, SPDX headers preserved) with the same API: the `stage` property, which ksplashqml raises from 1 to 6 (verified with a probe in `ksplashqml --test`, which exits after stage 6), so progress is `stage / 6`, and the fade-in starts at stage 2, as in Breeze. The background is an image from the wallpaper generator dimmed in Python (`splash.dim`), and not blob drawing in QML: the same look as the desktop, a single JPEG of about 100 KB, no banding from a semi-transparent overlay. Colors and dimensions from `Tokens.qml` generated from the palette (the `splash` section), no text on the screen. The installation writes `ksplashrc [KSplash] Theme` in the user file; a previous value equal to `org.tide.desktop` (e.g. from `~/.config/kdedefaults`, which Plasma fills in after a theme is chosen) is deleted on uninstall, not restored, because it would point to a removed package.
34. **Sidebar on the left monitor and Meta+S (26.10.2026, #18, extends 12).** A regular Plasma panel, not our own window: vertical, at the left edge of HDMI-A-1, `hiding=autohide` (KWin hides it behind the screen edge, exclusive zone -1, so windows do not lose space), floating, `lengthMode=custom` from the bottom of the slim bar to the bottom of the screen (`fill` always takes the whole screen and covered the global menu), marker `[Tide] role=sidebar`. The widgets are the same packages as in the dock with the `sidebarMode` setting: Plasma chooses the representation from `preferredRepresentation`, and the `switchWidth`/`switchHeight` thresholds were dropped, because in a vertical panel the applet height follows from the tile, so it would never cross the threshold. The detail views have a denser layout in bar mode, because four widgets have to fit in about 1000 px; agents take the rest of the height (the list scrolls).
    **Meta+S.** Plasma 6.8 has no "show hidden panel" call. Verified in the plasma-workspace/libplasma 6.8.1 sources: activating an applet with a global shortcut only toggles its `expanded` (`PlasmoidItem`) and does not reach the panel, and activating the panel itself (the "panel focus" shortcut) slides it out for 3 s (`PanelView::showTemporarily`), but that shortcut cannot be set from the scripting API (`globalShortcut` exists only on `Widget`) — writing `[Shortcuts] global` into the panel configuration would work only after a plasmashell restart. What does work is the status — in the same way a hidden panel stays on screen while an applet popup is open (`CompactApplet.qml` then sets `RequiresAttention`): `PanelView::restoreAutoHide` does not hide the panel as long as the container status (the highest among the applets) is at least `NeedsAttention`. That is why the bar has a first header widget `org.tide.sidebar` ("Tide" and a badge with the shortcut, as in the mockup), to which the installer gives `globalShortcut = "Meta+S"` (KGlobalAccel: `plasmashell` / `activate widget <id>`, stored in `kglobalshortcutsrc` and in the applet configuration). After activation the header raises its status to `RequiresAttention` for 8 s, a second press or the timeout returns it to `Active` — the panel hides on its own, unless the mouse is over it. Verified in a nested `kwin_wayland --virtual` with plasmashell (`make sidebar-preview`): invoking the shortcut action through KGlobalAccel slides the bar out, after the time it disappears, and after uninstalling the action disappears from KGlobalAccel. Rejected: a KWin script with `registerShortcut` (like Meta+A) — KWin has no access to the panel state, it would have to switch `hiding` through `evaluateScript` on every press, i.e. write the panel configuration and remember what to return to; the panel focus shortcut — only 3 s and no API; showing the bar through agents' "needs attention" — the bar would hang on the screen as long as someone is waiting, so in bar mode the agents do not report this status.
    Shortcut collisions are detected as with Meta+A (`kwin/shortcuts.py` on `kglobalshortcutsrc`, ignoring our own action from a previous installation); on a collision the installer does not set the shortcut and says where to free it. Uninstalling first removes the shortcut from the header, and then calls `unregister` in KGlobalAccel, so that Meta+S is not left occupied by the action of a removed widget.
35. **Wallpaper with the cat (26.10.2026).** A ready-made illustration of the user's cat (natural coat coloring as a deliberate exception to the palette, background in Mist colors) replaces the blobs in Mist, which stay as a working alternative: `wallpaper.variant` in the palette, `cat` or `blobs`, an unknown value is an error. The images are in the repository (`theme/wallpaper/assets/cat`, sums in `manifest.json`), so that installation and packages do not depend on the home directory, and a reinstall does not return to the blobs. Frames always from a single canvas: for the layout the images were prepared for, ready files without processing; for a different one — one scale for the whole canvas of monitors and a crop around the cat (`focus`), without stretching screens separately. The variant images live in `wallpapers/Tide/<variant>/`, because with the same address Plasma might not load a new image.
    States: eyes open on the desktop, in SDDM and on the loading screen; on the lock screen the cat sleeps while the form is hidden, and wakes with a crossfade when the greeter shows it (`uiVisible` from the Plasma code — no custom keyboard capture; since decision 37 it is awake only during active use of the screen). The state is shared across monitors (a singleton in a single QML engine of the greeter). Dimming exactly once: raw images and an overlay from the palette (lock `lockscreen.dim`, login `opacity.loginDim`, both 0.2 as in the design; since decision 49 — 0.12), the loading screen dimmed in Python (`splash.dim`); we do not use the dimmed PNGs from the package, because they are for only one monitor. We do not blur the cat (the `WallpaperFader` blur would cover the eyes). The sleeping version is a separate render shifted by about 2 px — the lock screen shifts it back (`sleepRegistration`); the background waves differ nonlinearly (0–5 px) and the fur is painted differently, so in the middle of the crossfade a slight softness remains, but the silhouette does not jitter (since decision 49 the sleeping version shares a base with the awake one and the correction is [0, 0]). Rejected: shifting the pixels of the sleeping version at assembly time (it would change the delivered files) and playing a video from the package.
    The login screen got a user picker from the real `userModel` (cards, keyboard, "Inny użytkownik" (Other user)), still on QtQuick only. A note from the previews: the Plasma greeter itself shows the form right after locking (an empty PAM message at start), so the cat fell asleep only after about 10 s of inactivity — the empty message is now skipped and the cat sleeps from the moment of locking; we do not change the authentication code from Plasma.
36. **"Waiting" only at a blockage, a new "finished" state (26.10.2026).** A Codex Desktop thread driven by a scheduled task ("Wysłane przez zaplanowane zadanie" (Sent by a scheduled task)) glowed peach after every turn with "czeka na ciebie · czeka na odpowiedź" (waiting for you · waiting for a reply), got a notification and was the target of Meta+A, even though it blocked nothing — and so did every finished Claude Code turn. Now `waiting` is exclusively a tool approval, a question (`AskUserQuestion`, `ExitPlanMode`, `request_user_input`) or a `waiting` status reported by Claude Code, and an ordinary end of a turn (status `idle`, `end_turn`, `task_complete`, interruption) is a new state `done` for 30 min, then `idle`. `done` does not notify, is not a target of Meta+A (also when nobody is waiting — the shortcut is meant to say "someone needs you"), does not mark the Konsole tab and does not reach the lock screen. Color: `semantic.done` → `sky` — a calm blue, clearly different from the "working" teal (mint is for "merged" in worktrees and at a small dot blends with teal), plus an empty circle instead of a dot. A turn from automation is recognized by `turn_attribution.turn_trigger = "automation_heartbeat_scheduled"` or `content_item_kinds` with `user.heartbeat` (verified on real logs, structure only) and gets the reason `scheduled` ("zaplanowane" (scheduled) on the card). The tile counts finished ones as sessions: "1 gotowa · 2 gotowe · 5 gotowych" (1 ready · 2 ready · 5 ready) — an adjective, because the past tense forces the gender of the agent ("2 skończyli" without a noun sounds foreign), it is shorter than "skończyły", and "pracuje/czeka" (working/waiting) in the tile also speak about sessions; the card speaks about the agent ("skończył" (finished), like "pracuje" (working)). A tile with three parts is wider (up to 240 px), so the budget of four tiles in the preview grew from 800 to 900 px.
37. **The cat on the lock screen dozes (26.10.2026, extends 35).** After a live trial: the cat had its eyes closed only briefly, because it followed `uiVisible`, and the greeter keeps the form for about 10 s after every action and as long as there is a password in the field — the crossfade was barely visible. Now the cat is awake only during active use of the screen: every own event of the lock screen (mouse movement other than the first, spontaneous position event, a click, a key that was not eaten by the field, typing and deleting in the password field through `textEdited` — not `textChanged`, so clearing the field from code does not count, a real authentication message) is a pulse `LockState.pulse()`, and after `lockscreen.dozeAfterMs` (3000 ms) without a pulse the cat falls asleep, although the form stays. It stays awake while password checking lasts (from `passwordResult` to `failed`/`succeeded`) and while the failed-unlock message is visible (`notificationRemoveTimer`, 3 s); afterwards, without a new action, it falls asleep at once. When the form disappears from all screens, the cat sleeps immediately, and a pulse while the form is hidden does nothing.     **Where it sits:** in `models.chat`, not in the report or in `summarize.Model` — every future call (PT-17, PT-19) gets the queue for free, and the Claude path (`claude -p`) stays unchanged. The queue has no threads of its own: a call waits on a condition variable and runs in the calling thread, so there is nothing to clean up at shutdown, and an error always frees the slot. The lane by the normalized server address (`scheme://host:port`), not by endpoint name — two names for the same server share one slot, because the server handles one request anyway. `chat()` determines the call target (endpoint, address, model, context) when the call gets its turn, not when it joins: with settings changed from the Tide window (PT-25, e.g. switching `default` to the Mac) waiting calls already go to the new server. The report pins the settings from the start of a run (one run = one set of settings): otherwise after a switch in the middle the facts would go to the Mac, and the footer would say "nothing leaves this computer", the memory and the trimming to the context would be for the old model (the PT-16 re-review). Card descriptions do not pin, but check the target before sending (`chat(expect=…)`: the endpoint, address, model and context assumed at the start of the batch): different from the assumed one — the call does not go out, rules with a note and nothing in memory under the wrong identity; the next batch already with the new settings. The reply (`Answer` with the actual target) is checked once more. A lane is an address without name resolution (`localhost` and `127.0.0.1` are two lanes). The next one is chosen by a single slot under a lock at every state change, and the end of the grouping window also counts as a change — the review found a deadlock when every waiter computed "the next" itself, against its own clock reading.
    **Time:** the call limit counts from its start, and waiting has its own limit from the caller: cards 5 min, then rules with an honest reason ("kolejka: czekał 300 s — serwer zajęty: raport poranny" (queue: waited 300 s — server busy: morning report)) instead of a misleading call limit; the report — 600 s for the whole including waiting (`deadline`), so it does not lengthen because of the queue. `models.Cancel` removes waiting ones at once, without reaching the server (a requirement from the PT-15 review: shutting down the service must be fast).
    **State:** `Status()` on `/Models` has an optional field `queue` (`{endpoint: {running, waiting}}`, only the role, model and since when — no command contents; next to the `report` and `pulls` fields from PT-25 (decision 66), the PT-18 tile works without both). `Changed` because of the queue at most once per second, because the report changes the queue several times per project. Entries in `queue` have `endpoint` (where the call came from), and endpoints on the same server show the same lane state. Starvation of the report (`LOW`) does not occur in practice: card descriptions are at most one call at a time. Outside the queue stay short state GETs, model pulling (`PullModel`, PT-25) and agent sessions with a local model (they talk to the server themselves). Making heavy work wait for user idleness (`idle.py`) — for later. The number: PT-27, PT-25 and PT-16 were created in parallel and every branch added "65" — when merging, numbered in merge order (65 PT-27, 66 PT-25, 67 PT-16).
    **Ollama cloud models (the PT-17 review):** `…:cloud` and `…:120b-cloud` after `pull` look in `/api/tags` like local ones, but the local Ollama only forwards them to ollama.com — a role with such a model would send the report facts to the cloud under the footer "nothing leaves this computer". One function (`modelnames.is_cloud_model` from PT-17, the label after the last ":" ends in `cloud` after ":" or "-", regardless of case; `models.config` imports it, and the view, tile and "Nowe zadanie" have one copy in JS: `widgets/lib/modelnames.js`, with trimming of whitespace in the name from the field): the role is unavailable with a reason, `chat()` refuses at join and at call start (also with an explicit model), `SetRole` refuses, `Status()` marks models `cloud: true`. The queue wait limit is now `queue.Busy` (a subclass of `ModelError`), to distinguish a busy server (try in a minute) from a non-working one.
    **The query and KRunner:** from 3 words and 12 characters, after 0.3 s of silence (KRunner asks at every key — a newer query invalidates the older one before anything goes to the server), with a memory of the last 64 vectors and priority `HIGH`. Match answers with words at once when the query does not qualify; otherwise it waits 0.3 s of silence and then at most 1.5 s for the vector (about 1.8 s in total) — KRunner should not wait longer for our plugin. The query goes through `strip_secrets`, and one that looks like a shell command, an address, a path or contains a secret does not go to the model at all (the PT-19 review: KRunner is sometimes a terminal and an address bar). A cold model (the first call: a few seconds, 2.3 s in the measurement, then about 20 ms) finishes in the background and warms up the server, and KRunner gets only words. The server does not respond or the model is missing — 30 s without attempts; no error reaches KRunner.
    **Ranking and merging:** cosine similarity. A threshold alone would be brittle — bge-m3 gives unrelated texts 0.3–0.4 and matching ones 0.45–0.6 (a measurement on sample sessions) — so a result must have at least 0.42, be 0.06 above the average of all sessions (the background of this query) and at most 0.08 below the best; at most 5. Words take precedence: a session from words is not repeated, semantic ones get the LOW category, relevance below the weakest session from words and the note "podobne znaczeniowo" (semantically similar) in the caption — the user sees where they came from.
    **Settings and state:** `semanticSearch` (a top-level key like `agentProgram`, on by default; it works when the model is on the server), `SetSemanticSearch("on"|"off")` on `/Models` and a row "Wyszukiwanie" (Search) in the "Modele" view: Włączone / Wyłączone (On / Off), a model choice and "Pobierz teraz" (Pull now) as with other roles and a single index state line (`Status().search`: `state`, `items`, `pending`, `updated`, `error`). A missing search model does not light the window badge or the tile (an optional role, decision 68). The number: 75 — when merging with master, 73 already had PT-43, and 74 PT-41.

96. **Risk-based review, coordinator fixes and test accounting (6.11.2026, K-71, PT-259).**
    Agreements from the review by Astra and the coordinator, approved by the user. This decision replaces
    the reviewer selection rule from decision 85; the other findings of 85 stay in force, and its historical text
    remains unchanged. For ordinary tickets an independent reviewer may use the same model
    with a different thinking strength (Codex strong ↔ standard), always in a new session. A reviewer from another model family
    (e.g. Astra / Claude relative to a Codex author) is mandatory for permission and security boundaries,
    destructive operations, migrations of persistent state, historical resumes and approval validity,
    concurrent git operations/locks/crash recovery, changes to test selection and acceptance gates,
    and integrations changing a shared card contract. The lack of an available limit for such a reviewer
    means waiting; the requirement does not drop automatically. **A change of 10.11.2026 (K-88/PT-330):**
    reviewer selection is the project policy `reviewIndependence` (`free` by default, `other-model`, `other-family`
    with an optional list of classes), not a Tide rule; the only fixed thing is a new reviewer session. The list of risk
    areas is **a recommendation for projects with the `other-family` policy**; when the required reviewer is missing the card
    gives the reason and asks the owner (change the reviewer, wait, relax the policy) instead of waiting silently.

    A coordinator fix outside the card serves only an urgent unblocking or a regression: one cause,
    at most 150 lines of production code in 3 files in total, without splitting into commits. It requires a test
    reproducing on the base and passing after the fix, a regression, and an entry in the register with the SHA of the base
    and of the fix, commands/results, the affected cards, delivery to their branches and rollback.
    An independent review ends within 24 h of delivery, earlier before merging a card
    that depends on the fix. An overdue review blocks further merges through this path; a BLOCKER/MAJOR after the fact
    stops the dependent work and requires a repair or rollback. The risk classes listed above,
    features and contract changes require a card and review before merging.

    A failed test remains a failed result. A deviation keeps the first result, a comparison
    of the same test on the base and `master`, the machine load, the scope and the owner of the fix.
    "Passes separately" is not enough; a close-out with a failed full run requires an explicit
    accounting and a user decision. The executive rules:

    [test exceptions](testing.md#test-exceptions),

97. **Review independence is a project policy, not a Tide rule (10.11.2026, owner, K-88).**
    It changes decision 96 in the part about reviewer selection. Tide does not impose who writes and who checks: it follows only
    the rules set for the project or in the plan. The owner's words: "this has no right to be some overriding rule
    of tide […] if it is set FOR THE PROJECT that there must be different families — fine, let someone enforce it […]
    if it is not set — FREEDOM". The reason: a user with one subscription from one provider cannot
    get stuck on a requirement of a reviewer from another family; a review by the same model in a new, isolated session is an exchange of
    cost for certainty, not an error. Always binding is only a new, separate reviewer session. The project setting
    `reviewIndependence`: `free` (default), `other-model` (today's `independent_reviewer`), `other-family`
    (optionally for selected classes). The list of risk areas from decision 96 stays as a recommendation for projects
    with `other-family`. A missing required reviewer: a readable reason and a question to the owner instead of silent waiting.
    Rollout: K-88 PT-330 (rewritten 10.11) with the gate from PT-312. Until the rollout in plasma-tide the Codex reviewers
    in unstarted tickets are replaced by an Anthropic model (the GPT limit 11% until 12.11 08:00).
