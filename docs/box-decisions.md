# Card box decisions (working draft, K-38)

Working file of decisions made while building the card box (`docs/card-box-design.md`). K-38 tickets append
rows here; only the documents ticket (#25, PT-188) moves them to `docs/decisions.md`, with continuous numbering.
The `Etykieta` (label) column is fixed — scripts and tests may refer to it (e.g. `tryb-admin` unlocks
`--project-mode admin` in `scripts/box/install.sh`).

## PT-170: ref guard (2026-11-05)

### AUTO: Other cards wait for this repository's guard to be released

- **Reason**: D7 allows the branches of active tickets of the same card. Simultaneous steps of different
  cards in the same repository would roll back each other's legitimate commits as foreign changes.
- **Effect**: `boxstep.place` queues the other card, and `refguard.begin` re-checks the condition
  under the lock. Parallel tickets of the same card remain allowed. Rule D7 is not extended.

### AUTO: Snapshots account for specific git operations performed by the service

- **Reason**: during a step Tide creates branches for subsequent tickets, writes the plan state to the card
  branch, merges finished tickets and removes their worktrees. These changes do not come from the agent.
- **Effect**: under the shared lock `gitops` updates in the snapshots only the named ref or the
  `config.worktree` of the removed worktree, when the value before the operation matched the snapshot.
  Other changes remain violations; we do not widen the set of refs the agent is allowed to touch.

  of PT-293; another SHA: `TIDE_ROLLBACK_OLD_SHA`), run in a separate `python3 -I` on the same authoritative
  journal (the service mirror). Artifacts: the full events in order, the SHAs of both versions, the old engine's report
  (`$TIDE_ROLLBACK_ARTIFACTS`).
- **Result without the procedure** (K-38 service stopped without a pause, a step in the box alive): the master fold reads all cards
  without exception (`FlowState` has no box fields), and the old engine: checks the box step's unit on the host
  (`systemctl --user is-active tide-step-…scope`), writes `error/lost` for the live step and starts a steward on the host
  (double work), after an answer resumes on the host the box step's session (`--resume` of the session from the box home),
  ignores `box.wait=environment` and `rebuild` (ticket start on the host after the answer or after resuming the card).
- **Result with the procedure** (pause → end of processes and `StopBox` → check → service stop → old engine → restart
  of the old engine): zero starts and `systemctl` calls, zero appended events, unchanged data outside the journal
  (state of the boxes and of the Incus dummy, refs, worktrees), complete history according to the fingerprint. A `safe` card resumed on
  the old code behaves as in K-38 with `box.enabled: false` (session resume on the host). The check refuses
  when there is no pause, when there is a pause without the end of a process and when a unit state is unknown — the old engine then does not move.
- **Limitations**: dummies, not a real Incus/systemd; we do not certify a rollback with an active step in the box
  (the procedure requires its end); reading all histories of the real Board is the subject of F7 (PT-295). The PT-261 trial
  block is not lifted: steps covered by `trialpolicy` have class `decision`.

### Rollback procedure (writing and installing only with the owner's separate consent)

Check and verification only read; we run the commands from the K-38 checkout (`PYTHONPATH=<checkout>/daemon`),
because after reverting the integration the `rollback.py` module is not in the installed code.

1. Pause every card with a flow in progress (Board or `SetCardPaused`). A pause does not end processes.
2. Confirm the end: no steps without a result, consoles and outside; step units (host and box), consoles and outside
   inactive (the unit's cgroup includes descendants); `box.use` released; boxes stopped with `tide box stop <project>`,
   slot and queue free.
3. `python3 -m tide_daemon.cardflow.rollback check > rollback-check.json` — `ok: true` required. Every `stops`
   entry, including an unknown state, stops the procedure before the downgrade.
4. Stop the service (`systemctl --user stop tide-daemon`) and repeat `check`: `ok: true`, the same `fingerprint`.
5. The Board copy only as comparison evidence. No rsync over the mirror, no deleting new events,
   no reset/rebase of branches and no automatic journal migration.
6. `python3 -m tide_daemon.cardflow.rollback revert-plan K-38` reads the card's `card.merged`. `MergeCardToMain` creates
   a merge commit `commit-tree -p <targetCommitBefore> -p <sourceCommit>` (also after the integration
   `integrate/k-38-master-v2`, which changes only the card branch): the command is `git revert -m 1 <resultCommit>`
   after checking that the first parent is `targetCommitBefore`. Integration without a merge commit: `git revert --no-edit`
   of the commits `targetCommitBefore..resultCommit`, newest first. No record or inconsistent parents: no command,
   the owner's decision. As of PT-293 there is no integration: the card candidate `d00270439dd7aaa99c6683b4419064b56e585e31`
   (ticket start), master `a6efe28cdfe2e727bbc1dec085ac3aebfb76abe6`; the exact SHA is given only by the merge record.
   Merging K-38 again after such a revert requires reverting the revert commit.
7. Before installing, repeat the trial for the first parent: `TIDE_ROLLBACK_OLD_SHA=<targetCommitBefore>`.
   Then `make install` (backup) and start of the old engine, then its restart. After each:
   `python3 -m tide_daemon.cardflow.rollback verify rollback-check.json` — `ok: true`.
8. `hold-paused` and `decision` cards stay paused. Only `safe` cards may be resumed.

### Verdict for the release

- **Batch 1** (`box.enabled: false`, no steps in the box): the history has only `safe` cards (`batch1Safe: true`).
  Rollback proven on dummies: the old engine and its restart without effects, card resume as in K-38.
- **Historical/pending meanings** (`hold-paused`): rollback is safe only when the pause is kept. Unblocking
  on the old code is dangerous (trial).
- **Must not be unblocked without a decision** (`decision`): steps in the box, resumes of sessions from the box, the PT-261 block.
  A safe resume of such cards on the old code cannot be proven. **Release blocker**: every batch
  with `box.enabled: true` (the first `box.wait` or a step in the box) has no proof of a safe rollback. For the owner's
  decision, without a fictitious APPROVE and without an automatic journal migration.

## PT-295: reading all histories and mirror consistency (2026-11-09)

### AUTO: The batch 1 gate reads every history with the code of exact SHAs and compares both copies

- **Tool**: `tide_daemon/cardflow/historyaudit.py` (driver `historyaudit_driver.py`), read-only.
  Run from the repository directory:
  `env PYTHONPATH=<repo>/daemon /usr/bin/python3 -m tide_daemon.cardflow.historyaudit --board <Board>
  --out <new directory outside the sources> --candidate <candidate SHA> --reference <reference SHA>`
  (`--mirror` defaults to `journal.mirror_root`). Exit code 0 only when the gate passes, report
  `report.json` and `report.md` in the output directory.
- **Denominator**: the sum of the mirror registries (`*.jsonl`) and the Board's `flow/K-*`, without a card list and without a fixed number.
  A card in only one copy, a card directory without a journal, an unknown registry entry, a listing or read error,
  a truncated line, an unknown format, a duplicate and a seq gap are separate errors, and the card stays in the denominator (`N/N`).
- **Copies**: for each card and source the number and range of seq, event types, SHA-256 of the full content. The Board is
  compared with the mirror event by event and field by field; the mirror is authoritative (the service reads from it),
  but a divergence is an error — the tool does not choose a copy and repairs nothing.
- **Code**: `git archive` of the candidate and the reference into the output directory; a separate `python3 -I -B` per version.
  Candidate: `trialhold.read_process_history` on a read-only journal and `fold`; reference: strict read
  and `fold`. The guard (audit hook) rejects file writes, filesystem changes, a child process, a socket
  and a D-Bus/Qt import; the `Journal` write methods are refusal dummies. An attempt is a `forbidden-operation` error.
- **State fields**: `FIELD_SPEC` assigns every `FlowState` field of both versions to a category (plan/ticket map,
  states, pause/close-out, steps/runner/identity, results/verdicts, decisions/consents, outside, consoles, box.wait,
  project links) and rules. A field without classification is an error. New candidate fields relative to
  `a6efe28c` have an expectation rule from the history: `box_wait`/`box_env_deferred` from the last `box.wait` after the
  last `card.started`, `process_identities` — every identity `ok` and named after a history step; the overlay of
  identity on step and intent entries (`_identityHeld`, start fields) is subtracted according to the identity data.
  A change of `moved_to`/`closed` at close-out after sending back for rework is explained only by the column's course.
  The method views (`running`, `open_consoles`, `open_intents`, `merge_pending`, `busy_reason`) are compared too.
- **Stability**: a fingerprint (content and metadata of the registries and journals) before and after; a change invalidates the run
  (`unstable`). Every candidate change requires a new run; a failed gate stops the release.
- **Tests**: `daemon/tests/test_cardflow_history_audit.py` — synthetic histories through the public journal write;
  red cases (card/field/event, runner, consent, truncated line, listing, change during the run, write
  attempts, a difference and an unclassified state field) and a full consistent copy with the new fields as green.
